title: Docket 可以從 ub-mode 與它的工具借用什麼

2026-10-31 記錄。維護者問 Docket 可以向 [ub-mode](https://github.com/unclebob/ub-mode) 借用什麼，並要求把它留成一個 idea。以下筆記來自閱讀它的 README 與 SKILL.md，以及它的工具的 README；這些工具都還沒執行過，以下沒有任何一項已決定。

## 它是什麼

ub-mode 是一份 SKILL.md：寫程式的簡短規則，分三部分（讓它能動、讓它正確、練習），搭配同一位作者的四個工具：

- **crapper**：每個函式的 CRAP 分數，`CC² × (1 − coverage)³ + CC`，所以既複雜又沒測試的函式分數高。它寫出 `.metrics/crap.edn`；`--changed` 把範圍限制在 git 新增與編輯的部分，`--threshold` 在超過某個分數時讓執行失敗。
- **dryer**：重複的候選，依正規化後結構的相似度計分。它寫出 `.metrics/dry.edn`。
- **mutator**：突變測試。`--changed` 把範圍限制在 git 新增與編輯的部分；之後的執行只重跑存活者與文字有變的函式；有突變體存活時以結束碼 3 結束。每個 worker 突變檔案的私有副本。它寫出 `.metrics/mutate/<namespace>.edn`。
- **uml-viewer**：依 policy 與各語言的解析器畫出元件，依 CRAP 與突變的快照上色，並把從較高層指向較低層的相依標成紅色。

前三者讀 Clojure、Java、Go、TypeScript、Rust 與 Python。uml-viewer 的解析器讀 Clojure、TypeScript、Rust 與 Python，不含 Go。這些工具是 Python 程式，第一次執行時會建立 `.venv` 並安裝套件。ub-mode 的 repository 沒有授權，所以它的想法可以用，但它的文字不能照抄。

## 線索

- **選擇要做 baseline 的對象。** agent 為一個小 package（174 行）寫的 baseline，每行程式碼約對應 18 個字的 proposal 與 spec，所以整份既有的程式碼無法一次做 baseline。每個函式與每個 package 的指標可以挑出要做的部分：高 CRAP 標示出最需要 spec 的複雜且未測試的程式碼；高突變分數標示出測試已經釘住其行為、可作為 spec 證據的程式碼；重複的候選值得在被寫成 spec 兩次之前先合併。ub-mode 的規則「先手動做一個單元，再建造與之吻合的工具」很合適：先手動做一個 package，工具必須給出同樣的地圖。
- **把快照當作選用輸入。** 這些工具寫出以 namespace 與函式名稱為鍵的穩定檔案，由 viewer 連接。`dkt` 產生不需要語言解析器的事實；快照存在時它可以讀，但絕不要求。workbench 也可以用同樣的方式顯示它們。
- **對改動行的突變檢查。** 流程範本要求對改動的行做突變會讓測試失敗。今天，突變體是每個 task 手寫的。mutator 的 `--changed` 加上它的重跑，可以替 Go 做這件事。它會被寫進使用者的流程檔，而不是作為 Docket 的相依隨附。
- **值得寫進流程範本或審查 prompt 的規則：**
  - 如果每個函式都回傳空值而測試仍然通過，那個測試什麼都沒測，這讓只改測試的審查所關注的「測試有沒有變弱」更銳利；
  - 當建立在同一個前提上的兩個修正沒通過同一項檢查時，在嘗試第三個修正之前，先用一句話寫下前提，這很接近修正迴圈的斷路器；
  - 一行一條規則、用祈使句，比 Docket 的散文短。

## 不採用

- 「最後推到主線」與 Docket 以 merge commit 合併 PR 的做法衝突。
- 對整份既有程式碼設硬性門檻（CRAP 低於 10、移除每個重複）會在採用時啟動大型的結構調整。只套用在改動的程式碼上，或作為不得變差的棘輪，比較合適。
- 寫程式的紀律本身（TDD、領域建模）留給 superpowers 與 agent；Docket 守在分流、路徑與記帳。

## 待釐清問題

- 這些工具的 Go 支援在這個 repository 上是否站得住腳：crapper 的複雜度與覆蓋率、mutator 的運算子、`--changed` 涵蓋的是改動的行還是整個改動的函式，以及一次執行要多久。
- `dkt` 是否該讀 `.metrics/` 快照，還是留給 agent 與 workbench。
- 流程範本是否該點名外部工具，還是描述檢查並把工具留給使用者的流程檔。
- 上述規則中，哪些屬於隨附的流程範本，而不是某一位使用者的流程檔。
